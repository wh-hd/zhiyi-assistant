# 智医助手后端安全加固增量 PRD

- **项目**：`zhiyi_assistant_security_hardening`
- **适用范围**：`deliverables/backend/nestjs`
- **文档性质**：仅描述现有安全修复后的增量变更，不重复既有功能 PRD
- **依据**：2026-07-10 两版代码审计报告、当前 NestJS/Prisma 实现、现有 H2/M6 修复说明

## 1. 现状与本轮范围结论

1. **管理员阈值权限的代码逻辑已成立**：`AdminGuard` 从 `ADMIN_USER_IDS` 读取逗号分隔的用户 ID，自动去除空白；配置为空或当前用户不在名单时返回 403；阈值读取仍对已登录用户开放。
2. **管理员配置交付尚未闭环**：NestJS `.env` 已声明 `ADMIN_USER_IDS=`，但 Docker Compose 的 API `environment` 未透传该变量；根目录旧 `.env.example` 也未提供一致配置。按当前 Docker 启动方式，即使运维只修改 `.env`，容器内仍可能无法启用管理员。
3. **H1 仍存在**：创建用药计划时，计划与当日依从记录分步写入且没有事务，中途失败会留下半成品数据。这是本轮下一个 High 优先级目标。
4. **M1-M5 处置结论**：
   - M1（自评会话未绑定用户）仍存在，纳入本轮 P1；生产多实例共享会话后置到 P2。
   - M2（报告慢病/过敏字段名错误）已修复，本轮不再变更，仅纳入回归。
   - M3（JSON `VARCHAR(4000)` 溢出）仍存在，涉及数据库迁移，列为 P2 独立变更。
   - M4（手术史/家族史/疫苗接种无法写入）仍存在，偏功能完整性，列为 P2 独立变更。
   - M5（微信接口无超时且异常降级为开发登录）仍存在安全与可用性风险，纳入本轮 P1。
5. **Refresh Token 基线已具备**：默认有效期为 2,592,000 秒（30 天），已实现数据库哈希存储、刷新轮换、登出撤销、重放后撤销该用户全部有效 Refresh Token，并记录 WARN。
6. **Refresh Token 运维闭环仍缺失**：没有清理过期记录的定时任务；重放检测也没有外部告警通知。

## 2. 目标

1. **保证核心写入原子性**：用药计划与其当日依从记录必须全部成功或全部失败，消除半成品数据。
2. **补齐安全配置与会话防护**：使管理员白名单在本地与 Docker 部署中行为一致，并关闭自评会话劫持、微信登录异常降级等已知风险。
3. **建立 Token 生命周期运维闭环**：在不削弱重放检测的前提下清理过期 Token，并让生产环境能及时感知重放事件。

## 3. 用户与运维故事

- 作为家庭健康管理员，我希望创建用药计划时不会留下缺少提醒记录的半成品，以便后续提醒和漏服判断可信。
- 作为普通登录用户，我希望无法通过猜测他人的自评会话 ID 提交答案，以免健康数据被篡改。
- 作为平台管理员，我希望只有被配置到 `ADMIN_USER_IDS` 的账号能修改全局指标阈值，以防普通用户误改安全规则。
- 作为部署运维，我希望同一管理员配置在直接启动和 Docker Compose 启动时均生效，并能确认“空名单即无人有权”的安全默认值。
- 作为安全运维，我希望系统定期清理已过期 Refresh Token，并在检测到重放时收到可行动的告警，以控制数据增长并及时响应账号盗用。

## 4. 需求池

### P0 — 本轮必须完成

#### P0-1 用药创建事务化（H1）

- 系统**必须**在同一数据库事务中创建用药计划及其当日全部 `pending` 依从记录。
- 任一数据库写入失败时，系统**必须**回滚该次创建产生的全部数据库记录。
- 缓存失效与“计划已创建”事件**必须**仅在事务成功提交后执行，禁止对已回滚计划产生成功副作用。
- 接口成功响应结构与既有调用方兼容；失败时返回统一错误，不暴露数据库细节。

#### P0-2 管理员配置交付闭环

- `ADMIN_USER_IDS` **必须**支持逗号分隔的一个或多个用户 ID，并忽略条目前后空白与空条目。
- 未配置、空字符串或仅含空白时，系统**必须**拒绝所有阈值修改请求（403），不得提供隐式超级管理员。
- 非名单用户修改阈值**必须**返回 403；名单用户可正常修改；阈值查询行为不得受影响。
- Docker Compose 的 API 服务**必须**透传 `ADMIN_USER_IDS`，并允许从部署环境配置；不得把真实管理员 ID 固化在版本库。
- 运维示例与说明**必须**使用当前真实变量名，明确：如何取得 `user.id`、多 ID 写法、修改配置后需重启实例、空值的 deny-by-default 行为。
- 启动或健康检查日志**可以**显示“管理员数量/是否启用”，但不得输出完整管理员 ID 列表。

### P1 — 本轮建议完成，生产发布前必须闭环

#### P1-1 自评会话绑定发起用户（M1）

- 新建自评会话时**必须**记录 `ownerId`。
- 提交每一步答案时**必须**校验当前登录用户与 `ownerId` 一致；不一致返回 403，且不得修改会话进度或答案。
- 会话过期与不存在继续使用现有 404 语义，避免向未授权用户泄露额外会话信息。
- 本轮可保留单实例内存存储；多实例共享与故障恢复列为 P2。

#### P1-2 微信登录超时与失败关闭（M5）

- 微信 `jscode2session` 请求**必须**设置可配置超时，默认 8 秒；超时、网络错误、非成功 HTTP 状态或非法响应均必须快速失败。
- 当配置了真实微信 AppID/Secret 时，任何微信调用异常**不得**降级生成 `dev_openid_*`，必须拒绝登录并记录不含 Secret、code、session_key 的安全日志。
- 只有在明确的开发环境且未配置真实微信凭证时，才允许既有开发登录模式。

#### P1-3 定期清理过期 Refresh Token

- 系统**必须**增加每日低峰期定时清理任务，默认时区为 `Asia/Shanghai`；建议执行时间为 03:30。
- 清理条件**必须**仅基于 `expiresAt < 当前时间`。已撤销但尚未过期的记录必须保留，以维持原有效期内的重放检测能力。
- 清理应支持批次执行并具备幂等性；在多实例重复触发时不得误删未过期记录或导致服务异常。
- 每次任务**必须**记录开始/结束、删除数量、耗时与失败信息；日志不得包含 Token 原文或 Token 哈希。
- 单次任务失败不得影响鉴权主链路，后续周期可自动重试。

#### P1-4 Refresh Token 重放生产告警

- 继续保留现有行为：检测已撤销 Token 重放后，先撤销该用户全部未撤销 Refresh Token，再返回 401，并记录 WARN。
- 生产环境**必须**将该安全事件发送到可配置的外部告警通道；通知失败不得阻塞或回滚 Token 撤销。
- 告警最少包含：事件类型、环境、脱敏用户标识、时间、请求 ID/追踪 ID；不得包含 Token 原文、Token 哈希、JWT Payload、微信凭证或其他密钥。
- 相同用户的高频重放告警**应该**聚合或限频，但首次事件必须及时通知；告警目标为事件发生后 5 分钟内可达值班渠道。

### P2 — 后续独立迭代

#### P2-1 自评会话迁移到 Redis（M1 完整方案）

- 用 Redis TTL 替代进程内 `Map`，使会话在多实例部署、滚动发布和进程重启时保持一致；同时保留 `ownerId` 校验。

#### P2-2 健康档案 JSON 字段扩容（M3）

- 将 `chronicDiseases`、`allergies`、`surgeries`、`familyHistory`、`vaccinations` 及知识标签等受影响字段迁移为适合长文本的类型，提供迁移前容量评估、备份、回滚与 JSON 完整性校验。

#### P2-3 补齐健康档案写入维度（M4）

- DTO、服务层和接口文档补充手术史、家族史、疫苗接种的写入与读取闭环，并验证 AI 咨询上下文能消费最新数据。

#### P2-4 其他已审计中低优先级项

- M2 不做新实现，仅持续回归。
- 其余 Low、前端和非本轮 High 项继续按审计报告排序进入后续迭代，不与本次事务/鉴权改动捆绑发布。

## 5. 验收标准

| 编号 | 验收场景 | 通过标准 |
|---|---|---|
| AC-01 | 正常创建不同频率的用药计划 | 计划创建成功；当日依从记录数量与排程时间点一致；均为 `pending` |
| AC-02 | 在第 N 条依从记录写入时注入数据库失败 | 接口失败；数据库中不存在本次计划，也不存在其任何依从记录 |
| AC-03 | 用药事务失败后的副作用 | 不发布“计划创建成功”事件；不产生指向不存在计划的通知；缓存行为不呈现半成品 |
| AC-04 | `ADMIN_USER_IDS` 为空、缺失或仅空白 | 任意登录用户修改阈值均返回 403；阈值查询仍成功 |
| AC-05 | 管理员名单含多个 ID 和空白字符 | 名单内用户修改成功；名单外用户返回 403；空条目不产生权限 |
| AC-06 | Docker Compose 启动并配置管理员 | 容器内读取到配置；授权结果与直接启动一致；仓库内无真实管理员 ID |
| AC-07 | 用户 B 使用用户 A 的自评 `sessionId` 提交答案 | 返回 403；会话答案与步骤保持不变；用户 A 仍可继续提交 |
| AC-08 | 真实微信配置下发生超时/网络异常/错误响应 | 最迟在“配置超时 + 1 秒”内失败；不得创建 `dev_openid_*` 用户；日志无敏感参数 |
| AC-09 | 清理任务处理过期与未过期 Token 混合数据 | 仅删除 `expiresAt < now` 的记录；未过期记录全部保留；重复运行结果一致 |
| AC-10 | 使用已轮换或已登出的 Refresh Token | 返回 401；该用户所有未撤销 Refresh Token 被撤销；产生 WARN 和一条可追踪安全事件 |
| AC-11 | 外部告警通道不可用 | Token 撤销与 401 仍成功完成；记录告警发送失败；鉴权服务不崩溃 |
| AC-12 | 回归 | 现有 H2/M6 六项测试、登录/刷新/登出、阈值读写、用药创建、M2 报告摘要相关测试全部通过；构建与类型检查零错误 |

## 6. 非目标

- 本轮不建设数据库角色/RBAC 管理后台；管理员来源仍为部署环境变量。
- 本轮不改变指标阈值为按家庭或租户隔离；仍沿用当前全局阈值模型。
- 本轮不改变 Refresh Token 默认 30 天有效期、JWT 协议或客户端刷新交互。
- 本轮不删除未过期的已撤销 Token，也不以“减少表数据”为由削弱重放检测。
- 本轮不实现安全运营中心、自动封禁账号或自动工单，只接入最小可用告警通知。
- 本轮不捆绑 M3 数据库迁移、M4 档案功能扩展及其他前端改造。

## 7. 风险

1. **事务边界风险**：若缓存和事件被错误纳入数据库事务，外部副作用失败可能造成不必要回滚；若在提交前执行，又可能产生幽灵事件。
2. **并发轮换风险**：同一 Refresh Token 被并发刷新时，非原子“检查后撤销”可能同时成功；实施阶段需验证并发下至多一次轮换成功。
3. **误清理风险**：提前删除尚未过期的已撤销 Token 会使重放从“可识别”退化为普通无效 Token，降低安全可观测性。
4. **告警风暴风险**：攻击者可重复提交旧 Token 触发大量通知，需要限频，但不得吞掉首次事件。
5. **配置漂移风险**：NestJS `.env`、Docker Compose 和根目录旧 `.env.example` 的变量命名不一致，若不统一会导致“文档已配置、运行时未生效”。
6. **数据库迁移风险**：M3 涉及 TiDB 字段类型变更和历史数据校验，不能与核心鉴权/事务修复无评估地混发。

## 8. 待确认事项

1. 生产重放告警接入哪个渠道：企业微信/飞书 Webhook、Sentry、Prometheus Alertmanager 或现有日志平台？值班接收人和升级策略是什么？
2. 是否存在多实例 API 部署？若是，Refresh Token 清理任务需明确分布式锁或允许幂等重复执行的批次策略。
3. 安全审计是否要求保留 Token 撤销记录超过其原始有效期？本 PRD 默认到期后即可删除；如有合规留存要求，应转存不含 Token/哈希的审计事件，而不是长期保留凭据哈希。
4. 微信登录超时是否统一为 8 秒，还是需要按环境配置不同值？
5. M3 数据库迁移和 M4 档案补全是否安排在紧接本轮的下一迭代，以避免健康档案持续存在容量和字段缺口？
6. 是否要求本轮一并解决 Refresh Token 并发轮换的原子性；建议在生产发布前纳入安全并发测试，即使不扩展接口。
