# 智医助手发布前增量加固 PRD

- **项目名称**：`zhiyi_assistant_release_hardening`
- **日期**：2026-07-10
- **文档性质**：现有产品 PRD 的发布前增量需求；不替代原产品定义
- **适用范围**：`deliverables/backend/nestjs`、`deliverables/frontend`、部署配置、数据库迁移与自动化测试
- **技术基线**：NestJS + Prisma + MySQL/TiDB 兼容数据库 + 当前单页前端原型
- **审计基线**：代码审计总结、工程报告、QA 独立验证报告及 `product-strategy/prd-zhiyi-assistant-2026-07-05.md`
- **当前发布结论**：**不允许发布**。现状为 3 Critical、13 High；安全回归 19/22；默认 Jest 与 Jest E2E 均为 0 tests；14 个 Prisma 模型无可从空库执行的建表基线。

## 1. 原始需求复述

本轮一次性消除当前审计确认的发布阻断项：清除仓库敏感凭据并完成真实轮换后的安全注入，封堵家庭角色提权，建立完整 Prisma 基线迁移并在隔离空库验证，修复自评/家庭建档/用药/指标一致性，修复 XSS、SSE 生命周期与前端认证闭环，补齐 Jest/E2E 和全部 Critical/High 回归，最后依据明确门禁重新评估是否具备发布条件。

## 2. 产品目标

1. **恢复安全边界**：版本库和部署产物不再携带有效敏感值；普通家庭成员无法提权；认证、XSS 与 SSE 不再存在已知 High/Critical 风险。
2. **恢复核心健康数据可信度**：家庭建档、自评、用药、指标在失败、并发、跨日、乱序和多实例场景下保持一致、可重试、可审计。
3. **建立可复制的发布证据**：全新隔离数据库可由迁移自动建立；Jest、E2E、安全与 Critical/High 回归可重复执行，只有全部硬门禁通过才允许灰度。

## 3. 用户故事

- As a 家庭普通成员, I want 角色与他人健康数据受到最小权限保护 so that 任何家庭成员都不能越权提权或篡改敏感信息。
- As a 家庭健康管理者, I want 自评、成员档案、用药与指标数据在异常和并发下仍然一致 so that 我看到的健康结论、提醒和趋势可信。
- As a 登录用户, I want 登录过期能安全刷新、退出能撤销会话、故障不伪装成成功 so that 我不会在失效或伪认证状态下继续操作。
- As a 部署运维, I want 用平台密钥管理注入轮换后的凭据，并能从空库部署 so that 新环境、灾备和轮换不会依赖仓库秘密或手工建表。
- As a 发布负责人, I want 一套不可绕过、证据可追溯的自动门禁 so that Critical/High 缺陷不会再次进入生产。

## 4. 范围与优先级

### 4.1 P0 — 发布阻断，必须全部完成

| ID | 需求 | 必须达到的结果 |
|---|---|---|
| P0-01 | 凭据清除、轮换与安全注入 | 从当前版本及可发布产物移除数据库、JWT、Redis、MinIO 等敏感值；模板只留变量名/无效示例；生产使用平台 Secrets/环境注入；相关真实凭据由所有者轮换并留存完成证据；Redis、MinIO Console/API、Ollama 默认不暴露公网。历史 Git 是否清洗由安全负责人按传播范围决定，但**不能以仅删除当前文件代替真实轮换**。 |
| P0-02 | 家庭授权与角色提权修复 | 新增成员、变更任意成员角色仅 admin 可执行；普通 member 不得修改自己或他人的角色；普通成员只可修改本人允许字段；保护最后一个 admin；角色变化写入不含健康内容的安全审计日志。同步定义健康档案、用药、指标、自评的角色-资源-动作策略，至少阻止普通成员写他人数据。 |

| P0-04 | 自评与家庭建档一致性 | 创建家庭时原子创建主成员与 HealthRecord；自评服务端逐题校验题型、步骤、必答项和选项；前端使用 start/answer/result 真实 API；分数持久化契约支持既有一位小数且不失真；Assessment 完成、HealthRecord 快照及会话清理在同一可恢复事务/幂等边界内。 |

| P0-06 | 用药一致性 | 按计划有效期生成/获取每天排程；次日及后续日期不漏物化；过期/未开始计划不进入今日任务；`planId + scheduledAt` 建立数据库唯一约束并使用原子 upsert；并发确认最多一条依从记录。 |
| P0-07 | 指标与告警一致性 | streak 只使用当前记录之前且同成员同类型数据，支持历史乱序重算；批量记录与后处理同一事务；告警按 member+type+业务窗口幂等；多实例调度采用原子领取/唯一键，避免漏报和重复通知。 |
| P0-08 | XSS 修复 | 后端来源的药名、剂量、单位、备注及其他动态文本禁止直接进入 `innerHTML`；默认使用 `textContent`/安全 DOM API，必要 HTML 经统一 allowlist 净化；移除动态内联事件；增加 CSP（不依赖 `unsafe-inline` 作为最终方案）和恶意字段浏览器回归。 |
| P0-09 | SSE 全生命周期闭环 | 前端解析器跨任意 chunk 保留状态、按完整 frame 分发 `event/data`；解析失败显式上报；页面退出/切换/超时可取消。后端从 HTTP 断连贯通 AbortSignal 至 generator、fetch 与 reader，调用 cancel/return；写入前检查响应可写，异常过滤器尊重 `headersSent`。 |
| P0-10 | 前端认证闭环 | 生产彻底禁用 `dev-token`/故障登录 fallback；区分 401、网络、服务异常；实现 access token 到期后的单飞 refresh、轮换结果保存和一次安全重放；refresh 失败清空会话并回登录；logout 必须调用服务端撤销且本地必清理。修复微信混合配置开发身份与响应体读取超时；修复 refresh 清理竞争。 |
| P0-11 | 测试基础设施与回归 | 建立可工作的 Jest/ts-jest 根配置，排除 `dist`；补齐 `test/jest-e2e.json` 和可隔离运行的测试启动/清理机制；修复安全测试 3 项失败；为所有 3 Critical、13 High 建立自动化回归，无法完全自动化者必须有可重复隔离验证脚本和审签证据。 |
| P0-12 | 发布复评 | 工程修复后由 QA 在固定提交上独立执行两轮；两轮均满足第 8 节门禁，产品、安全、工程、QA 与平台所有者完成签字后，才可进入受控灰度。 |

- 本轮不新增 OCR、语音识别、微信订阅消息发送、PDF 报告、可信内容体系、多轮 LLM 上下文等尚未闭环的产品能力；生产 UI/文档不得宣称已交付。
- 本轮不扩展在线问诊、诊断、处方、电商、心理治疗等原 PRD 非目标。
- 不连接、探测或在日志/文档复述疑似泄露的真实凭据；验证必须使用轮换后的隔离 Secrets 或一次性虚构值。

- 不以单元 mock 代替所有关键 E2E、真实数据库约束和浏览器 DOM/SSE 验证。
- 不因本轮完成而自动宣称原 PRD 全部 P0 已交付；本 PRD 只判定当前实现能否安全进入灰度。

## 6. Given / When / Then 验收标准

### AC-01 凭据清除与注入
- **Given** 全新检出仓库且未注入 Secrets，**When** 扫描受版本控制文件、镜像层和构建产物并尝试生产启动，**Then** 不发现真实敏感值，生产因缺少必需 Secret 明确 fail-fast，且日志不输出秘密。
- **Given** 平台已注入轮换后的独立 DB/JWT-access/JWT-refresh/Redis/MinIO 凭据，**When** 启动隔离环境，**Then** 服务仅从受控注入读取并正常就绪；JWT 不回退 `dev-secret`，访问与刷新签名密钥不得复用。
- **Given** 默认 Compose/生产网络策略，**When** 从非授权网络探测 Redis、MinIO Console/API 与 Ollama，**Then** 端口不可达或仅绑定受控内网/localhost。

### AC-02 真实轮换责任
- **Given** 旧值按已泄露处理，**When** 平台所有者轮换并撤销旧值，**Then** 新环境使用新值成功、旧值验证失败，且提供不含秘密的轮换时间/资源/执行人/验证结论及访问日志审查记录。

### AC-03 家庭角色权限
- **Given** 普通 member 的有效 token，**When** 其添加成员、把自己或他人改为 admin/caregiver、或修改他人受保护资料，**Then** 返回 403，数据库零变化。
- **Given** admin，**When** 合法添加成员或变更非最后管理员角色，**Then** 成功且生成审计记录；**When** 降级/删除最后一个 admin，**Then** 返回 409/422 且家庭仍保有 admin。

### AC-04 Prisma 空库基线
- **Given** 无任何表和迁移历史的一次性 MySQL 兼容空库，**When** 仅执行正式 `prisma migrate deploy`，**Then** 一次成功创建 14 个模型所需表、外键、唯一约束与索引。
- **Given** 已部署基线并完成最小 seed，**When** 应用启动、执行认证/家庭/自评/用药/指标最小 CRUD、再次 deploy 并检查 drift，**Then** CRUD 通过、第二次 deploy 无变更、Schema 与数据库无未解释 drift。

### AC-05 家庭建档与成员事务
- **Given** 新用户创建家庭，**When** 任一嵌套写成功，**Then** Family、主成员、HealthRecord 同时存在；**When** 任一步注入失败，**Then** 三者均不留下半成品。
- **Given** 两个并发添加/删除请求，**When** 请求结束，**Then** memberCount 与真实成员数一致、每个成员有唯一档案、排序满足确定性策略，失败请求无副作用。

### AC-06 自评闭环
- **Given** 新家庭主成员且无预先读取档案，**When** 前端依次调用 start/answer/result 完成正常自评，**Then** 结果真实落库、HealthRecord 快照同步、结果页来自 API，刷新页面仍可读取。
- **Given** 正常答案计算得到 `7.8`，**When** 提交完成，**Then** Assessment 与 HealthRecord 均精确保存约定精度，不报类型错误、不静默取整。
- **Given** 空答案、错误 step/type、题库外选项、缺必答题或跨用户 session，**When** 提交，**Then** 返回 400/403/404 的既定语义，评分和进度不改变。
- **Given** Assessment 或 HealthRecord 写入中途失败/同一完成请求重试，**When** 事务结束，**Then** 要么全成功一次，要么全回滚；不得产生重复 completed Assessment。

### AC-07 用药一致性
- **Given** 有效期跨 3 天的每日计划，**When** 分别查询三天今日任务，**Then** 每日正确产生且仅产生当日排程；开始日前和结束日后不展示。
- **Given** 50 个并发请求确认同一 `planId + scheduledAt`，**When** 全部结束，**Then** 数据库最多一条依从记录且最终状态符合定义，不产生唯一约束 500。
- **Given** 每日物化任务重复运行或多实例并发运行，**When** 完成，**Then** 结果幂等、无重复、无漏服告警遗漏。

### AC-08 指标与通知一致性
- **Given** 同成员同类型指标按乱序时间写入，**When** 重算 streak，**Then** 仅按业务时间顺序计算，结果与顺序写入一致。
- **Given** 批量写第 N 条或后处理失败，**When** 事务结束，**Then** 整批按约定全回滚；不得保留默认 streak/漏处理子项。
- **Given** 双实例同时扫描同一异常窗口，**When** 触发通知，**Then** 相同 member+type+窗口最多一条有效告警；不同成员/类型互不串扰。

### AC-09 XSS
- **Given** medicineName、dosage、notes 含 `<img onerror>`、`<svg onload>`、引号闭合和脚本 URL 等测试载荷，**When** 浏览器渲染列表与详情，**Then** 仅显示文本/被净化内容，无脚本或事件执行、无 token/健康数据外发，CSP 无新增违规放行。

### AC-10 SSE 生命周期
- **Given** `event:`、多行 `data:`、空行分隔符在每个字节边界任意拆包，**When** 前端接收，**Then** `red_line/disclaimer/chunk/done/error` 类型、顺序和数据均正确且只分发一次。
- **Given** 用户切页、取消或网络断开，**When** SSE 尚在生成，**Then** 前端请求被 abort，后端 generator/fetch/reader 在限定时间内停止，之后无 write-after-close、无未处理异常；隔离验证中断连后底层活动应在 1 秒内观察到取消信号。
- **Given** headers 已发送后发生上游错误，**When** 全局过滤器处理，**Then** 不重复写 JSON 响应，连接被安全结束并保留可追踪日志。

### AC-11 认证闭环
- **Given** 后端不可用、微信配置混合缺失/占位或登录响应非法，**When** 用户登录，**Then** UI 显示失败且不生成 dev token、不创建开发身份用户。
- **Given** 微信 headers 已返回但 body 挂起，**When** 超过配置超时，**Then** 登录在“超时 + 1 秒”内失败，连接被取消且日志无 code/secret/session_key。
- **Given** 多请求同时收到 access token 401，**When** refresh 有效，**Then** 只发送一次 refresh，等待请求至多各重放一次且使用轮换后 token；**When** refresh 失败/重放，**Then** 清空本地认证并回登录。
- **Given** 登录用户点击退出，**When** 服务端可达或暂时不可达，**Then** 可达时 refresh token 被撤销；无论结果本地凭据均清理并提示状态，不继续伪装登录。
- **Given** refresh 清理首批被竞争实例先删除且后续仍有过期记录，**When** 清理执行，**Then** 不因 `count=0` 提前结束，最终处理后续记录且有防空转上限。

### AC-12 参数边界与上传（P1 能力门禁）
- **Given** NaN、负数、小数、超上限分页/days/batch 或倒置时间窗，**When** 请求接口，**Then** 返回 400 且 Service/数据库未收到非法参数。
- **Given** 私有健康文件上传，**When** 匿名访问 URL、伪造 MIME/扩展名或上传恶意内容，**Then** 匿名访问失败、内容检测拒绝；授权用户仅通过短期签名/鉴权下载。

### AC-13 测试与复评
- **Given** 干净检出和隔离配置，**When** 执行项目声明的 build、Prisma、Jest、security、E2E 与浏览器测试命令，**Then** 均实际收集并执行预期用例，不扫描 `dist`，不存在 0 tests 假通过/假失败。
- **Given** 固定候选提交，**When** QA 连续两轮独立回归，**Then** 两轮结果一致且满足第 8 节全部硬门禁；任何源码/迁移/配置变化都使已有签字失效并至少重跑受影响门禁。

## 7. 凭据轮换责任矩阵

| 事项 | 代码/仓库团队可完成 | 平台所有者必须完成 | 完成证据（不得含秘密） |
|---|---|---|---|
| 仓库当前版本清理 | 删除硬编码值；改为变量/Secret 引用；提供无效示例；加 secret scanning | 审批允许的变量来源与命名 | 扫描报告、变更清单 |
| Git 历史处置 | 统计敏感文件路径、提出 history rewrite 方案并通知影响 | 决定是否重写历史、冻结推送、强制成员重新拉取及清理镜像/缓存 | 决策记录、完成范围 |
| 数据库凭据 | 支持 `DATABASE_URL` 安全注入、缺失 fail-fast | 在 TiDB/MySQL 平台创建新账号/密码、最小权限、撤销旧账号/会话、检查异常访问 | 资源标识、轮换时间、旧凭据撤销验证、日志审查结论 |
| JWT secrets | 分离 access/refresh 配置、最小长度/弱值检查、启动 fail-fast | 生成高熵新 secrets、注入各环境、使旧 token 全部失效并安排重新登录 | 注入版本/时间、旧 token 失效验证 |
| Redis | Secret 引用、TLS/认证参数、默认不暴露宿主公网 | 轮换密码/ACL、限制网络来源、终止旧连接、检查访问日志 | ACL/网络策略编号、旧值拒绝验证 |
| MinIO/对象存储 | Secret 引用、私有桶和授权访问代码；移除固定默认值 | 轮换 access/secret key、撤销旧 key、核查桶策略/访问日志 | 新 key 版本、旧 key 禁用、策略审查结论 |
| 微信 AppID/Secret | 严格配置校验、日志脱敏、失败关闭、超时覆盖 body | 在微信平台重置 Secret、更新回调/白名单（如需）、注入并验证旧 Secret 失效 | 平台轮换记录、隔离登录结果 |
| 外部 Webhook/模型服务 | Secret 引用、日志脱敏、网络最小暴露 | 轮换 token/key、限制来源；Ollama 内网化 | 轮换记录、网络策略验证 |
| 生产发布授权 | 生成门禁报告并阻断缺证据部署 | 确认全部旧值撤销、完成安全日志审查并签字 | 平台所有者签字、发布单号 |

**默认责任决策**：代码团队不得代替平台所有者“模拟”真实轮换，也不得用新值写入仓库；若任一平台轮换/旧值撤销证据缺失，门禁直接 FAIL。

## 8. 发布门禁定义

### 8.1 硬门禁（任一失败即 NO-GO）

| 门禁 | 放行阈值 |
|---|---|
| 凭据 | 仓库/产物 secret scan 为 0 个已确认有效秘密；所有受影响真实凭据完成轮换、旧值撤销与平台签字；对外不必要端口不可达。 |
| Critical/High | 审计 3 Critical、13 High 均有处置：代码修复并自动回归通过；若能力选择禁用，入口、路由、部署开关及声明必须同时不可用且有产品/安全签字。开放的 Critical/High = 0。 |
| 数据库 | 全新空库 `migrate deploy`、seed、核心 CRUD、二次 deploy、drift 检查全部通过；迁移可追溯且无 `db push`/手工补表。 |
| 构建/静态 | 构建、类型检查、Prisma validate 全部 PASS；生产配置缺 Secret 时安全 fail-fast。 |
| 自动测试 | 默认 Jest、security、Jest E2E、前端浏览器安全/协议测试全部实际执行且 100% PASS；不得有 `.only`、无解释 skip 或 0 tests。 |
| 关键专项 | 家庭提权、XSS、自评小数与事务、家庭建档、用药跨日/并发、指标乱序/双实例幂等、SSE 拆包/取消、refresh/logout/微信超时均 PASS。 |
| QA 独立性 | 固定候选提交连续两轮结果一致；QA 报告明确 `Release Gate: PASS`，无 Router=Engineer 的未解决项。 |
| 回滚准备 | 应用、配置、凭据和数据库回滚/前滚方案均演练通过；备份可恢复；负责人、触发阈值和命令/Runbook 可用。 |

### 8.2 放行结论

- **当前结论**：NO-GO。
- **满足硬门禁后**：只允许先进入受控灰度，不直接全量。
- **灰度默认**：10% 流量、至少观察 24 小时；出现认证失败率/500/数据一致性告警显著高于基线，任一安全告警或迁移异常，立即停止扩量并按第 9 节回滚。
- P1 中某能力未完成时，必须在生产显式关闭该能力；例如私有上传未完成则禁用上传，不允许以“后续修复”带风险上线。

## 9. 回滚要求

1. **提交与制品**：发布制品不可变并绑定 Git SHA；保留上一稳定制品、配置版本和依赖清单，可一键回退应用。
2. **数据库**：上线前完成加密备份及恢复演练。基线用于新空库，不得在已有生产库盲目标记已应用；所有后续迁移优先使用可前向修复的 expand/contract。若迁移含不可逆 DDL，必须在执行前给出经 DBA 审核的恢复步骤和最大可接受数据丢失窗口，未审不得发布。
3. **凭据**：不得通过恢复旧泄露凭据回滚。新 Secret 注入失败时应回滚应用/配置兼容性或重新签发新 Secret；旧 JWT 已失效时接受用户重新登录。
4. **数据写入**：涉及分数类型、唯一约束、告警幂等的变更必须有上线前重复/非法数据检查；发现冲突先停止写入或回滚流量，不得删除健康数据以强行迁移。
5. **前端**：保留上一静态制品；前后端协议须向后兼容至少一个发布窗口，或使用功能开关先停用新自评/SSE/认证入口。
6. **触发条件**：任一 Critical 安全事件、越权/XSS 复现、迁移失败或 drift、核心写入产生不一致、refresh 大面积失败、SSE 资源持续泄漏，均立即停止灰度并回滚。
7. **回滚验证**：回退后必须执行登录、家庭读取、核心健康数据只读、旧/新 token 安全状态、数据库完整性与告警检查；形成事件记录后方可再次提测。

## 10. UI 设计草案（仅本轮必要状态）

- 登录页：移除任何生产开发登录成功态；展示可区分的“登录失效 / 网络不可用 / 服务异常”，提供安全重试。
- 自评页：以服务端 session 驱动步骤；提交中防重复；校验错误定位到题目；结果页从后端读取并支持刷新恢复。
- 用药与家庭页：动态字段按纯文本渲染；无权限操作不展示，后端仍强校验；并发/网络失败展示可重试而非乐观成功。
- AI 咨询页：SSE 显示连接/生成/完成/已取消/错误状态；切页主动取消；`red_line` 与免责声明保持独立高优先级展示。
- 全局：演示数据与真实数据不得混显；错误不得静默吞掉；认证失效统一回登录。

## 11. 待确认事项（仅保留外部决策）

| ID | 必须确认的问题 | 安全默认决定 / 截止点 |
|---|---|---|

其余实现细节采用安全默认，无需再次询问：自评分数保留一位小数；JWT access/refresh secrets 分离；生产禁用开发身份；上传未私有化则关闭；非法查询返回 400；最后管理员受保护；所有真实秘密只经平台注入。
